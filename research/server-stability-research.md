# 服务器对外暴露稳定方案调研报告

> 数据调研师：力齐早早 | 日期：2026-08-01 | 指令来源：@futao（服务器不稳定问题）

---

## 一、问题定位（已确认）

| 层 | 状态 | 说明 |
|:---|:-----|:-----|
| ① 本地服务 | ✅ 稳定 | localhost:1111 持续 200，未崩溃 |
| ② tunnel 暴露层 | ❌ **不稳定（真因层）** | 见下方详细分析 |
| ③ 机器资源 | ✅ 未观测到瓶颈 | |

**② 层已实证根因（@lamda 踩坑记录）：**
- 当前网络会静默终止**空闲的长连接**（约 60s 无流量即掐断）
- cloudflared 的 HTTP/2 长连正好是"空闲长连"→ 被掐 → 530 掉线
- QUIC 被 UDP 阻断、localtunnel 被墙，试过无效
- **已验证缓解：** `--heartbeat-interval 1s` 保持每秒有流量 → 实测稳定 80s+ 不掉

## 二、各方案对比分析

### 方案 1：cloudflared quick tunnel（免费）— 现状

| 维度 | 评估 |
|:-----|:-----|
| 稳定性 | ⭐⭐ 60s 静默掉线；加 heartbeat 后可缓解但不根治 |
| URL | ❌ 每次重启随机变化，验收链接需反复更新 |
| SLA | ❌ 免费层无 SLA |
| 成本 | ¥0 |
| 复杂度 | 极低（一行命令） |
| 结论 | **只能应急，不能作为持续验收通道** |

### 方案 2：cloudflared named tunnel（固定域名）⭐ 短期推荐

| 维度 | 评估 |
|:-----|:-----|
| 稳定性 | ⭐⭐⭐⭐ 绑定固定域名，配置在 Cloudflare 侧，掉线自动重连 |
| URL | ✅ **固定不变**，一次配置永久使用 |
| SLA | 免费 tier 无正式 SLA，但比 quick tunnel 稳定一个量级 |
| 成本 | 仅需**域名费**（.top/.xyz/.fun 等 ≈ ¥50-100/年，Cloudflare 代管 DNS 免费） |
| 复杂度 | 中（需注册 Cloudflare + 添加域名 + 配置 tunnel → DNS CNAME），一次性配置约 30-60 分钟 |
| 数据流 | cloudflared → Cloudflare 全球边缘 → 本地 localhost:1111（HTTPS 自动管理） |
| 注意 | 国内访问走 Cloudflare 边缘，速度受运营商影响；可加 `--edge-ip-version 4` 规避 IPv6 握手问题 |
| 结论 | **性价比最高的中期方案**——固定 URL 解决反复发链接问题 |

### 方案 3：frp 自建（公网 VPS 中转）— 备选

| 维度 | 评估 |
|:-----|:-----|
| 稳定性 | ⭐⭐⭐⭐ 完全自己掌控，systemd 保活 + 自动重启后可达 7x24 |
| URL | ✅ 固定（VPS 公网 IP + 自定义端口/域名） |
| 成本 | VPS 费用：境外 ≈ $5-10/月；国内需备案 |
| 复杂度 | **高**（需维护 frps 服务端 + frpc 客户端 + 防火墙 + TLS 证书） |
| 优势 | 无第三方隧道服务依赖、带宽可控 |
| 结论 | 适合技术能力强的长期场景；但对当前团队偏重，**短期不推荐** |

### 方案 4：付费内网穿透（cpolar / 花生壳 / natapp）— 备选

| 维度 | 评估 |
|:-----|:-----|
| 稳定性 | ⭐⭐⭐⭐ 付费版稳定、固定域名、国内节点访问快 |
| URL | ✅ 固定域名（带专属二级域名） |
| 成本 | 免费版限速/限流不稳定；付费版约 ¥50-300/年 |
| 复杂度 | 低（注册 → 装客户端 → 拿链接） |
| 优势 | 国内访问速度快、无需自建服务器 |
| 结论 | 如果未来面向国内用户分发，这是好选项；个人验收场景**性价比低于 named tunnel** |

### 方案 5：云服务器托管（腾讯云/阿里云轻量）⭐ 长期推荐

| 维度 | 评估 |
|:-----|:-----|
| 稳定性 | ⭐⭐⭐⭐⭐ 专业 IDC 机房，SLA 保障，一劳永逸 |
| URL | ✅ 固定 IP + 域名 |
| 成本 | 轻量应用服务器：**活动价 ¥99-150/年**（2C2G3M 足够跑 Next.js + SQLite）；域名 ≈ ¥50-100/年 |
| 复杂度 | 中（服务器部署 + 域名解析；**国内节点需备案**，约 1-2 周；香港/海外节点免备案但略贵/延迟稍高） |
| 优势 | ① 不再依赖本地机器和隧道 ② 数据在云端有备份空间 ③ 后续 Phase 2-6（AI/RAG/桌宠）天然需要在线服务 |
| 结论 | **最彻底的解决方案**——从"本地开发+隧道暴露"升级为"云端部署"，与产品长期演进方向一致 |

## 四、推荐建议

### 分三步走（从简到难，不浪费现有投入）

**第 1 步（立即，今天）— 免费隧道 + 心跳保活**
- 沿用现有 quick tunnel，但**统一加上** `--heartbeat-interval 1s --retries 100 --grace-period 5s`
- 作用：解决 60s 静默掉线这个最痛的问题（lamda 已验证有效）
- 成本 ¥0，改动 1 行命令

**第 2 步（本周内）— cloudflared named tunnel + 自己的域名**
- 购买一个便宜域名（.top/.xyz ≈ ¥50-100/年，或 futao 已有域名直接绑定）
- 配置固定 URL 隧道，**彻底告别"每次重启发新链接"**
- 一次性配置 30-60 分钟，后续永久受益
- 判断：成本最低、见效最快，**强烈推荐作为过渡方案**

**第 3 步（1-2 个月内，随 Phase 3-4 启动）— 云服务器托管**
- 腾讯云/阿里云轻量服务器（活动价 ¥99-150/年）+ 域名解析
- 把服务从本地迁移到云端，摆脱"机器必须开机 + 隧道必须在线"的依赖
- 与 Phase 2-6（AI、RAG、桌宠需要常驻在线服务）方向天然一致
- 国内节点需备案（约 1-2 周），可提前规划

### 关键判断

1. **不要长期依赖免费隧道** — 免费层无 SLA，URL 易变，只适合开发期临时验收
2. **named tunnel 是"花小钱办大事"** — 域名费极低，却换来固定 URL 和数量级的稳定性提升
3. **云托管是终局** — 个人日记产品的数据安全 + 后续 AI 功能需要常驻服务，本地机不是长期方案

## 五、附带建议（针对 AI 总结 502 长请求问题）

- serveo 隧道对长请求超时 → 已确认，换隧道解决
- 若用 named tunnel / 云托管：Cloudflare 免费层对代理请求有 **100s 超时**限制，AI 总结这类长请求仍需注意。缓解：前端流式输出（SSE）或把长任务改异步任务队列 + 轮询状态
