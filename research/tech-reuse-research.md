## 二、可复用开源方案对比

### 方案 A：基于 Memos 改造（17.8K ⭐）

| 维度 | 说明 |
|------|------|
| **GitHub** | [usememos/memos](https://github.com/usememos/memos) |
| **技术栈** | Go 后端 + React + SQLite |
| **平台** | Web（Docker 自托管）+ 移动端 Web |
| **核心能力** | 卡片式碎片记录、Markdown、标签、资源上传 |
| **⭐⭐ 复用评分** | **8/10** |
| **可直接复用的** | 卡片列表 UI、Markdown 编辑器、标签系统、SQLite 存储层、搜索 |
| **需要改造的** | 加日历视图、日记结构化（日期维度）、心情/情绪标签 |
| **改造成本** | 中（3-5 天工作量） |
| **优点** | 用户量大，社区生态好，Docker 一键部署 |
| **缺点** | Go 后端——团队现有的是 Next.js 技术栈（需学习 Go） |

### 方案 C：直接使用现有组件库从零搭建（高度可控）

不是 fork 整个项目，而是复用成熟的开源组件组合成日记应用：

| 功能模块 | 推荐复用组件 | 成本 | 成熟度 |
|---------|------------|------|--------|
| 前端框架 | **Next.js** + Tailwind CSS | 0（团队已会） | ⭐⭐⭐⭐⭐ |
| 本地数据库 | **Dexie.js**（IndexedDB 封装）或 **SQLite (via sql.js)** | ~1 天集成 | ⭐⭐⭐⭐⭐ |
| Markdown 编辑器 | **MDXEditor** / **TipTap** / **BlockNote** | ~1 天集成 | ⭐⭐⭐⭐ |
| 日历组件 | **react-day-picker** | ~0.5 天 | ⭐⭐⭐⭐⭐ |
| 图片上传 | 本地 file system + IndexedDB | ~0.5 天 | ⭐⭐⭐ |
| 全文搜索 | **minisearch** / **lunr.js** 前端全文搜索 | ~0.5 天 | ⭐⭐⭐⭐ |
| 富卡片 UI | shadcn/ui 直接复用 | 0（团队已用） | ⭐⭐⭐⭐⭐ |
| PWA 支持 | **next-pwa** / **service-worker** | ~1 天 | ⭐⭐⭐⭐ |
| 日记卡片排版 | Framer Motion 动画（团队已掌握）| 0（团队已会） | ⭐⭐⭐⭐⭐ |

**⭐⭐ 复用评分：8/10** — 每块都是成熟方案，组合即可，改造成本低


| 技术栈 | 选型 |
|--------|------|

| 样式 | Tailwind CSS + shadcn/ui |

## 四、差异化切入点分析

在"卡片式随手记"这个方向上，结合调研结果，以下是可以做差异化的切入点：

### 🎯 差异化定位

| 方向 | 现有做法 | 我们的机会 | 难度 |
|------|---------|-----------|------|
| **极致极简** | flomo/备忘录已有 | 但 flomo 偏笔记，纯日记体验不够 | 低 |
| **日历记忆** | Day One 有 On This Day | 开源项目几乎没有 | 低 |
| **本地优先** | 大多数日记软件强制登录/云 | 日记天然需要私密，这是一个大卖点 | 低 |
| **AI 日记回顾** | Memex/Diarum 雏形 | 2026 年这个方向在爆发前期，入场好时机 (Phase 2) | 中 |
| **中文体验** | 开源项目大多是英文/国际 | 中文日记的 UI 文案、输入习惯、日期格式等细节可以做 | 低 |
| **语音速记** | DailyVox 纯语音 | 文字+语音混合输入，覆盖更多场景 | 中 |

### 🥇 Phase 1 差异化建议：针对 futao 自己的使用场景

**推荐三个低成本亮点：**

1. **「极速记录」** — 打开即写，无需建文档/选笔记本（对标 flomo 的「3 秒记录」）
   - 首页就是编辑区+卡片流，没有多余的页面跳转
2. **「卡片日历」** — 日历视图直接预览日记标题/摘要
   - Daily_You/侠客日记有日历，但卡片+日历的混合视图还没人做精
3. **「日记卡片长什么样，你说了算」** — 卡片主题色/背景图可自定义
   - 这是在 futao-homepage 学到的心得：个性化是高级感的来源

### 🥈 Phase 2 差异化（未来方向）

4. **AI 日记回顾** — "今天发生了什么？""最近一周心情趋势？"— 基于 RAG 的自然语言对话（Blinko 已有基础）
5. **语音日记转文字** — 说一段话，AI 自动整理成日记卡片

## 五、最终建议

### 技术路线建议

```
┌────────────────────────────────────────────────────────┐
│  ⭐ 推荐路线：Blinko fork + 组件增强                    │
│                                                        │
│  第 1 步 → Fork Blinko（获得完整 Next.js 全栈框架）     │
│  第 2 步 → 改造 UI 为日记卡片风格（miky 设计）          │
│  第 3 步 → 集成日历视图（react-day-picker）             │
│  第 4 步 → 本地存储 + PWA 离线支持                      │
│  第 5 步 → 情绪/心情标签 + 按日分组                     │
│                                                        │
│  预估工期：5-7 天（一人全栈 + 设计）                     │
└────────────────────────────────────────────────────────┘
```

### 库存备件（可零成本复用的）

以下都是团队现有能力/项目可直接复用的：
- ✅ **Next.js + Tailwind** 开发经验（futao-homepage）
- ✅ **Framer Motion** 动效能力
- ✅ **shadcn/ui** 组件库
- ✅ **TypeScript** 全栈

### 不做的事（减少浪费）

- ❌ 不研究 Joplin（太重，跟日记定位不符）
- ❌ 不考虑侠客日记（.NET MAUI 技术栈不可用）
- ❌ 不写 OAuth/登录系统（个人日记不需要）
- ❌ 不搭云端同步（Phase 1 不需要）
