# futao-logs 质量标准体系 V1

> 三级标准：不合格 ❌ → 合格 ✅ → 优秀 ⭐
> 参考来源：futao 验收反馈 + miky 设计规范 + Amily QA 标准 + 行业最佳实践

---

## 1. 用户体验 (UX)

| 维度 | ❌ 不合格 | ✅ 合格 | ⭐ 优秀 |
|:----|:---------|:--------|:--------|
| **响应速度** | 操作后 >2s 无反馈 | 操作后 1s 内有 loading/反馈 | 操作 <300ms，无需 loading |
| **空状态** | 空白页面无提示 | 有插画/文案引导 | 有引导 + 快捷入口（立即写日记） |
| **错误反馈** | 无提示或控制台报错 | Toast/alert 提示"操作失败" | 人性化文案 + 重试按钮 |
| **加载态** | 白屏 >3s | Skeleton / Spinner | 骨架屏 + 渐进加载 |
| **过渡动画** | 突兀跳变 | 150-300ms ease-out 统一 | 有节奏感、先后顺序考究 |
| **交互一致性** | 不同位置同功能行为不同 | 同功能全局交互一致 | 符合行业直觉（用户无需学习） |

## 2. 视觉设计 (UI)

| 维度 | ❌ 不合格 | ✅ 合格 | ⭐ 优秀 |
|:----|:---------|:--------|:--------|
| **颜色使用** | 硬编码色值 / 非 tokens | 全部使用 tokens.css 变量 | tokens + 双重主题均调色 |
| **间距布局** | padding/margin 随意 | 间距对齐 4 的倍数体系 | 呼吸感恰到好处（不拥挤不空旷） |
| **组件状态** | 缺少 hover/active 态 | 每个组件有 hover/focus/active | 有 pressed 微反馈 + 过渡动效 |
| **响应式** | 某个断点布局断裂 | 手机/平板/桌面 三档正常 | 每个断点经过调优设计 |
| **文字层级** | 字号/颜色混乱 | 63%-88% 透明度阶可用 | 清晰的信息层级（视觉引导） |
| **暗色主题** | 未实现/强行反色 | 两套独立调色 | 所有页面双重验证通过 |

## 3. 代码质量 (Code)

| 维度 | ❌ 不合格 | ✅ 合格 | ⭐ 优秀 |
|:----|:---------|:--------|:--------|
| **类型安全** | 使用 any / 无类型 | TypeScript strict 基本通过 | 全类型覆盖，无类型错误 |
| **构建** | 构建失败 / 有 warning | 构建通过 (vite build) | 构建 + lint + tsc 全部通过 |
| **组件拆分** | 大文件 >800 行 | 组件按功能拆分 <400 行 | 职责单一、可复用、有注释 |
| **状态管理** | 全局 state 混乱 | 组件局部状态明确 | 状态逻辑与 UI 分离 |
| **错误处理** | catch 块为空 / 用户看不到失败提示 | API 调用有 try-catch + 用户可见反馈 | 错误边界 + 重试 + 友好文案 |
| **命名规范** | 拼音/无意义命名 | 英文语义化命名 | 名称自文档化、统一前缀 |

## 4. 后端质量 (Backend)

| 维度 | ❌ 不合格 | ✅ 合格 | ⭐ 优秀 |
|:----|:---------|:--------|:--------|
| **API 功能** | 请求失败 / 数据不准 | 正常响应 + 数据正确 | 分页/筛选/排序全部可用 |
| **数据完整** | 空字段报错 / 乱码 | 字段完整返回 | 关联数据（tags/attachments）级联正确 |
| **请求校验** | 无输入校验 / 500 崩溃 | 基本 zod schema | 全面输入校验 + 友好错误信息 |
| **错误处理** | 出错时无日志 | try-catch + console.log | 结构化日志 + 可恢复错误提示 |
| **性能** | 无分页加载全部 | 分页查询 (take/skip) | 索引优化 + 大数据量不垮 |

## 5. Git & 工程管理 (Engine)

| 维度 | ❌ 不合格 | ✅ 合格 | ⭐ 优秀 |
|:----|:---------|:--------|:--------|
| **提交粒度** | 大段混提 / 无 git | 功能/修复独立提交 | 每个提交一个完整逻辑变更 |
| **提交信息** | 无意义消息 | `feat: / fix: / style: / chore:` 规范 | 信息清晰 + 可追溯 |
| **文件忽略** | 提交 node_modules / .env | .gitignore 配置完整 | .gitignore 定期维护 |
| **数据清洁** | 测试脏数据不清理就提交验收 | 提交前清理脏数据 | 验收环境始终干净 |

## 6. 测试验证 (QA)

| 维度 | ❌ 不合格 | ✅ 合格 | ⭐ 优秀 |
|:----|:---------|:--------|:--------|
| **测试方法** | 仅代码审查，无浏览器实测 | API 直调验证 + 浏览器 smoke test | Playwright 自动化覆盖 P0 |
| **核心闭环** | 保存后不验证 | 创建→保存→刷新→确认持久化 | 自动闭环 + 边界场景覆盖 |
| **场景覆盖** | 只测正常路径 | 空状态/加载态/错误态/边界值测试 | 离线/弱网/暗色/响应式/全覆盖 |
| **构建验证** | 提交前不跑 build | build 通过后提交 | lint + tsc + build 全部通过 |
| **主动改进** | 发现问题不汇报 | 报告 bug 并有初步诊断 | 附带修复建议或已修复 |
| **控制台日志** | Console 有报错/警告 | 无 console.error | 无任何 warning |
